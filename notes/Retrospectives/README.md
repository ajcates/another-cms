# Retrospective Summaries

This directory contains summaries of project retrospectives. Retrospectives are a key part of the agile development process, providing an opportunity for the team to reflect on what went well, what didn't go so well, and what can be improved in the next sprint or project phase.

## Structure of a Retrospective Summary

A good retrospective summary should include:
- **Date of the retrospective.**
- **Attendees.**
- **What went well?** (Things to continue doing)
- **What could be improved?** (Things to change)
- **Action Items:** (Specific, measurable, achievable, relevant, and time-bound tasks for improvement)

Keeping a record of these summaries helps the team to track its progress and ensure that it is continuously learning and improving.
