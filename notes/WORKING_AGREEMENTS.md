# Team Working Agreements

This document outlines the processes and expectations for how our team works together. These are living agreements, and we should revisit and update them as the team and project evolve. The goal is to make our collaboration as smooth, efficient, and transparent as possible.

## Communication

-   **Primary Channel:** Our main channel for daily communication is [e.g., a specific Slack/Discord channel].
-   **Meetings:**
    -   **Weekly Sync:** We have a weekly team sync every [e.g., Wednesday at 10:00 AM PST].
    -   **Note-Taking:** A rotating note-taker will be assigned at the beginning of each meeting. Notes should be saved in the [`Meeting Notes`](./Meeting%20Notes/) directory by the end of the day.

## Development Workflow

-   **Branching:** We follow a [e.g., GitFlow, GitHub Flow] branching model. All new work should be done on a feature branch created from `main`.
-   **Pull Requests (PRs):**
    -   All PRs must be reviewed and approved by at least one other team member before being merged.
    -   PRs should include a clear description of the changes and a link to the relevant task in our project management tool.
-   **Code Reviews:** Reviews should be constructive and timely. The goal is to improve the code, not to criticize the author.

## Documentation Practices

-   **Architecture Decision Records (ADRs):**
    -   An ADR is required for any decision that significantly impacts the system's architecture. Examples include:
        -   Adding a new service or data store.
        -   Integrating a new third-party dependency.
        -   Changing the API contract.
    -   ADRs should be proposed in a PR and reviewed by the team before being accepted. They are stored in the [`ADRs`](./ADRs/) directory.
-   **Retrospectives:**
    -   We will hold a retrospective at the end of each sprint or major project milestone.
    -   Summaries will be documented and stored in the [`Retrospectives`](./Retrospectives/) directory. The action items from each retrospective should be added to our task board for the next sprint.

By adhering to these agreements, we can foster a more collaborative and productive environment. If you have any questions or suggestions for improvement, please bring them up at our next team sync.
